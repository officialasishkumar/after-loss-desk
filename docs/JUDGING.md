# Against the published criteria

The hackathon judges four equally weighted criteria (rules, re-read 22 Oct 2026), with a friction-log bonus of up to 10% and ties broken by Tech, then Design.

| Criterion | What the rules ask | What this entry shows |
|---|---|---|
| **Tech implementation** | "how effectively does it use the required tech" | A stateless Streamable HTTP MCP server (spec 2025-11-25; a real MCP client drives it in `tests/test_web_and_mcp.py`), eight tools with closed schemas, an MCP App resource (`ui://afterloss/card.html`, `text/html;profile=mcp-app`, `_meta.ui.resourceUri` on every tool), checkout endpoints modelled on the Alexa+ checkout flow (create, update, complete; Idempotency-Key replay for 24 h, 409 on a changed body), not yet the full Universal Commerce Protocol (no GET or discovery profile, dollars rather than minor units, case id in the body rather than account linking), an Agent Skill (`SKILL.md`), a deterministic governor with a hash-chained receipt log, and a replayable eight-week simulation whose scoreboard is enforced by the build. |
| **Design** | "a complete, coherent product experience", "intuitive for the target device" | Built to the Alexa+ add-on design guide: end-to-end task completion (the list, the notices, the purchase, the decisions, all finished here), one title and one action per card, far-field type, voice replies under thirty seconds with at most five items, closed enums (no open text by voice). The executor says six things at the start and then only "approve" or "decline". |
| **Potential impact** | "credible, specific case", "audience beyond the hackathon" | 3.09M deaths a year; about 500 hours and 18 months per executor (Empathy, 2026). Insurers and employers already pay for bereavement support (Empathy serves 50M+ policyholders); funeral homes and estate attorneys refer. The rule table is a JSON file per state. |
| **Quality of the idea** | "creative, imaginative use of the required tools", "understanding of the developer ecosystem and end-user needs" | Hits four items on the rules' own Alexa+ creative list: state across sessions (months), orchestration across services (institutions, court, county, bureaus), purchasing (certified copies through Alexa+ checkout), MCP Apps; plus an Agent Skill. Built to the add-on policy: no names or account numbers by voice, legal lines quoted not advised, 988 in the first reply, no life-safety claim. Closest prior build we found: Postscript (AWS Agents for Humans, Sep 2026); see Prior art in [PITCH.md](PITCH.md). |

**Not claimed:** connection to a real Alexa+ device or the MCP Toolkit (preview, partners only); real institutions (simulated adapters); states other than California; the s.16 purchase rules (written confirmation, refund policy before purchase) and the s.3 privacy policy link and consent prompt (see [POLICY.md](POLICY.md)); any proof of what a real Alexa+ assistant says beyond the `speak` strings (its design guide says an add-on cannot script that).
